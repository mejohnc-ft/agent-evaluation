## Patterns that worked

- **Evals before prompt changes.** Each prompt or KB fix started from a failing scenario (9a93e34,
  08b6bc6, 5144d6f), so "fixed" meant a red check turned green, not a reply that looked better.
- **Assertions change only with a reason.** G7 blocks removed assertions without an `Eval-change:`
  trailer. Three over-narrow patterns were widened that way (251bfb3, 07eb638, a8cf2aa), each
  noting what still fails.
- **Contract first, then parallel agents in worktrees.** The `Store` contract (e8af04f) and the
  `AppEvent` / UI types (a45d9d5) landed before the data, guard, CI and UI agents started, so
  their tracks merged with one lockfile conflict.
- **Measure a flake before fixing it.** Tier 2 at 89% was run five times to separate variance from
  a pattern; the pattern became a deterministic check (`phantom_card`) and the variance went to
  temperature 0 (f5388d5).
- **A second pass on screenshots and measurements.** The UI agent's screenshot review caught the
  "above" wording (576c710), and Playwright measurement caught the 375 px overflow (8ae2a8a).
- **Red tests before the module.** Guards (85b9369), BotID (0063763) and retention (7f6e5d7) each
  committed failing tests first, with the red output quoted in `Verified:`.
- **Narrow a check before committing it.** `handoff_claim_after_result` and `phantom_card` were
  both narrowed once they flagged correct replies; the commit says what still fails.
